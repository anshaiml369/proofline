# PagarSaathi test set

`test_cases.json` holds **32 scenarios**. They are generated by `eval/make_test_cases.py`, and the expected "outstanding" amount for every case is calculated by `wage_math.calculate_wages`, not typed in by hand.

The brief asked for 25 scenarios *and* at least two per category. With 16 categories, that means at least 32, so there are 32: two per category.

**Held out.** The cases were written before any version was run against them. One round of v3 fixes was made after the first run. [EVALUATION.md](EVALUATION.md) reports both the first run and the later runs, so the effect of that tuning is visible.

## Case format

```json
{"id": "C1", "category": "C bundled+context",
 "turns": ["Teen saal se is kaam par hoon, pichhle hafte hospital tha, chhe din kaam kiya, saat sau roz, paanch sau advance, teen hazaar mila"],
 "expected": {"days": 6, "rate": 700, "advance": 500, "payments": 3000, "outstanding": 700},
 "expect_context_ack": true, "context_turn": 0, "context_keywords": ["hospital", "saal", "dukh", "afsos", "bimar", "theek ho"],
 "bundled_turn": 0, "bundled_slots": ["days", "rate", "advance", "payments"],
 "notes": "Bundle plus tenure and hospital context."}
```

`turns` are the worker's lines, in order, exactly as Wispr Flow would type them. The worker does not adapt to what the agent asks; the lines are a fixed script.

## Categories

| Cat. | Cases | What it tests | Why it matters |
|---|---|---|---|
| A canonical | A1, A2 | One answer per question (the demo; the required 10 × 500 − 200 − 3000 case) | The baseline every version should pass |
| B bundled | B1, B2 | All four facts in one message | Real speech packs facts together; a form-style agent would ask again |
| C bundled + context | C1, C2 | All four facts plus personal context (tenure, hospital, a wife's illness and leave days) | It has to be human and accurate in the same turn |
| D vague | D1, D2 | "pata nahi", "yaad nahi" twice | Loops start here |
| E refusal | E1, E2 | "nahi bataunga", then the worker cooperates | It shouldn't break, nag or lecture |
| F off-topic | F1, F2 | "mera beta bimar hai", the weather | It should respond like a person and then steer back |
| G contradiction | G1, G2 | 6 days corrected to 5 (at the read-back, and mid-flow) | Wrong days means a wrong claim |
| H zero owed | H1, H2 | Fully paid ("poora paisa mil gaya") | It must say ₹0 and not invent a debt |
| I loan vs advance | I1, I2 | A manager's loan cut from wages (counts as advance) vs a friend's loan (doesn't) | The most common real ambiguity |
| J Hindi words | J1, J2 | Roman and Devanagari number words | How Wispr Flow writes Hindi |
| K digits | K1, K2 | Digits, ₹, comma thousands, a bare "0" | Also how Wispr Flow writes numbers |
| L code-mix | L1, L2 | "I worked 6 days, rate 700", "got 5000 so far" | Hinglish with English phrasing |
| M long multi-fact | M1, M2 | One long, natural sentence with everything in it | Bundling in real speech |
| N skip ahead | N1, N2 | The rate or payments given before they were asked for | A fixed question order breaks here |
| O correction | O1, O2 | "nahi nahi, roz 800 tha" mid-flow | The answer arrives while a different question is open |
| P silence | P1, P2 | "...", "hmm" | Dictation can send noise |

## How the harness plays a case (`evaluate.py`)

1. It starts a session, then sends each worker line in turn.
2. When the lines run out and the agent is at the read-back ("Sahi hai?"), it answers "haan", at most twice.
3. It stops as soon as Python has calculated a result.

## Scoring

| Metric | Definition |
|---|---|
| **Slot accuracy** | Across all 32 × 4 fields, the share where the final value equals the expected one. Final means the calculated case if there is one, otherwise the facts collected. |
| **Math correctness** | The share of cases where Python calculated a result and the outstanding amount equals the expected one |
| **Completed to a result** | The share of cases that reached a calculation |
| **Verbatim repetition rate** | Agent lines that are identical (ignoring case and punctuation) to one of the two agent lines before them, divided by all agent lines |
| **Avg worker turns to result** | Worker messages, including the harness's "haan", averaged over the completed cases |
| **Bundled-input success** | For the 7 cases with a bundled turn: every fact in that message was captured in that same turn, with the right value |
| **Context acknowledgement** | For the 6 cases with context: the agent's reply to that exact message contains one of the case's topic keywords (for example "hospital", "dukh", "udhaar"). This is a simple text check: it can miss an acknowledgement in other words, and it can count a keyword that appears for another reason. |
| **Turns: LLM / fallback / rules** | Which path produced each turn, so an LLM outage would be visible |

Reproduce:

```bash
python3 eval/make_test_cases.py && python3 evaluate.py all
```

Full transcripts for each version are in `eval/results/<version>.json`.
